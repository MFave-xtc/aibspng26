# AIBS Digital Setup Guides — QA Checklist

**Version:** v1.0  
**Status:** Active draft  

---

## 1. Page-Level QA

Each website page must pass:

- [ ] Page title is clear.
- [ ] Purpose is obvious in the first screen.
- [ ] Mobile layout is readable.
- [ ] Text contrast is accessible.
- [ ] Navigation works.
- [ ] Buttons work.
- [ ] Images have alt text.
- [ ] No placeholder text remains.
- [ ] No broken links.
- [ ] Contact form works if present.
- [ ] Footer disclaimer is visible.

---

## 2. Guide-Level QA

Each guide must pass:

- [ ] Target user clearly stated.
- [ ] Difficulty level included.
- [ ] Estimated time included.
- [ ] PNG reality check included.
- [ ] Step-by-step instructions included.
- [ ] Safety warning included where relevant.
- [ ] What to buy included where relevant.
- [ ] What not to buy included where relevant.
- [ ] Troubleshooting included.
- [ ] When to call a technician included.
- [ ] Printable checklist included.
- [ ] Source register included.
- [ ] Assumptions register included.
- [ ] Review notes included.
- [ ] No unsupported claims.
- [ ] No overclaiming.
- [ ] No “best provider/product” claim unless verified.
- [ ] No legal advice presented as legal advice.
- [ ] No cyber incident response advice beyond basic public safety guidance.
- [ ] No child safety guidance that replaces professional or official advice.

---

## 3. PNG Context QA

Every guide must check:

- [ ] Does this advice assume reliable electricity?
- [ ] Does this advice assume unlimited internet?
- [ ] Does this advice assume easy replacement equipment?
- [ ] Does this advice assume high digital literacy?
- [ ] Does this advice account for shared devices?
- [ ] Does this advice account for second-hand equipment?
- [ ] Does this advice account for mobile-first users?
- [ ] Does this advice account for small budgets?
- [ ] Does this advice account for local support limitations?

If yes to any unsafe assumption, rewrite the guide.

---

## 4. Safety QA

Check for:

- [ ] No request for users to share passwords, OTPs, or recovery codes.
- [ ] No instruction to bypass security controls.
- [ ] No instruction to install pirated or cracked software.
- [ ] No unsafe hacking or intrusion guidance.
- [ ] No collection of unnecessary personal information.
- [ ] No advice that encourages surveillance without privacy consideration.
- [ ] No advice that exposes children or vulnerable users.

---

## 5. Source QA

Every factual claim must be one of:

- [CONFIRMED] Supported by official, regulator, vendor, standards, or highly credible source.
- [SUPPORTED] Supported by credible established public source.
- [INFERRED] Reasoned from validated evidence.
- [ASSUMED] Reasonable project assumption, not presented as fact.
- [REQUIRES USER CONFIRMATION] Must be checked before final use.
- [INSUFFICIENT DATA] No reliable evidence found.

Do not publish claims tagged [REQUIRES USER CONFIRMATION] unless the page clearly presents them as assumptions.

---

## 6. Brand QA

- [ ] AIBS logo appears correctly.
- [ ] Dark navy/black background used appropriately.
- [ ] Gold accents used consistently.
- [ ] Red used mainly for warnings or risk labels.
- [ ] Gold PNG map and Bird of Paradise used tastefully.
- [ ] Body text remains readable.
- [ ] Page does not look overcrowded.
- [ ] Tone is practical and PNG-grounded.

---

## 8. Release Rule

No guide is published until:

1. All high-risk claims are cited, removed, or tagged.
2. No placeholder content remains.
3. Owner approval is recorded.
4. The guide passes mobile readability review.
